# Organoid-Segmentation

Organoid-Segmentation is a Python workflow for brightfield brain organoid image segmentation and downstream morphology analysis. It supports both deep-learning segmentation with MMSegmentation/SegFormer and configurable classical segmentation for threshold-based brightfield workflows.

The repository is organized around three tasks:

- train and evaluate segmentation models for single-organoid brightfield images
- segment new experiments using either deep-learning or classical pipelines
- extract and plot organoid morphology metrics across days, batches, and experimental conditions

## Main Capabilities

- Deep-learning segmentation using MMSegmentation and SegFormer checkpoints.
- Classical brightfield segmentation for different magnification values (1.25x, 4x, etc)
- Stitching support for tiled microscope acquisitions such as `2x2` or `5x5` tile grids.
- Project-level metadata configuration through `experiment_metadata.json`.
- Support for one organoid per image and multiple organoids per well/image.
- Export of binary masks, labeled masks, raw-vs-mask comparison images, and segmentation summaries.
- Morphology extraction at object and well/image level, including area, diameter, perimeter, circularity, solidity, eccentricity, Feret diameter, aspect ratio, roundness, and skeleton length.
- Longitudinal plotting, group comparisons, outlier reports, detection summaries, and quality-control plots.
- Resume mode for interrupted segmentation runs.

## Installation

Create and activate a Python environment, then install the pinned dependencies:

```bash
python3 -m venv myenv
source myenv/bin/activate
pip install -r Organoid-Segmentation/requirements.txt
```

The current `requirements.txt` was synchronized against the local `myenv` environment used for this project. It includes the OpenMMLab stack (`mmengine`, `mmcv`, `mmdet`, `mmsegmentation`) plus scientific Python and plotting dependencies.

If you only need classical segmentation and morphology analysis, the deep-learning dependencies are still listed because the repository also contains training and inference code for the MMSegmentation model.

## Data Layout

Raw experiment data are expected outside the repository, under the base directory configured in `data-analysis/experiment_info.py`.

A typical experiment folder looks like this:

```text
Project_name/
    experiment_metadata.json
    raw_data/
        Day <day>/
            <batch_or_condition>/
                Tile000001.jpg
                Tile000002.jpg
                ...
    processed_data/
        ... generated by the pipeline ...
```

Image names, day folders, and batch names must match the project metadata. See `data-analysis/raw_data_folder_organization.txt` and `data-analysis/README.md` for the full convention.

## Running an Analysis

From `data-analysis`, run segmentation first:

```bash
cd Organoid-Segmentation/data-analysis
python3 segmentation.py
```

Select the project from the interactive menu. The script reads the selected project's `experiment_metadata.json`, generates masks, and extracts morphology metrics.

To continue an interrupted run:

```bash
python3 segmentation.py --resume
```

To force regeneration of morphology metrics from existing masks:

```bash
ORGANOID_FORCE_MORPHOLOGY=1 python3 segmentation.py
```

After segmentation and morphology extraction, generate plots and reports:

```bash
python3 morphology.py
```

Plot features, grouping variables, aggregation levels, and outlier settings are configured directly in `morphology.py`.

## Configuration Model

Each experiment should have a project-level `experiment_metadata.json`. This file defines:

- batches or conditions
- days/time points
- segmentation method: `dl` or `cl`
- magnification and pixel-to-micron calibration key
- tile grid and stitching parameters
- number of images/wells per plate
- whether each image contains single or multiple organoids
- classical segmentation thresholds and filters
- grouping variables used by morphology plots

The template in `data-analysis/experiment_metadata.json` can be copied into a project folder and edited for a new experiment.

## Outputs

For each processed day and batch, the pipeline writes outputs under:

```text
processed_data/Day <day>/<batch>/
```

Common output folders include:

- `inference_jpg/`: binary mask images
- `inference_npy/`: binary masks as NumPy arrays
- `inference_tif/`: binary masks as TIFF images
- `inference_labels_npy/`: labeled object masks
- `inference_comparison/`: raw image and mask comparison previews
- `inference_metrics/`: per-object and per-well morphology CSV files

Project-level plots and quality-control outputs are written under `plots/`.

## Training and Testing

The `train-and-test` folder contains scripts for dataset splitting, model training, checkpoint testing, and checkpoint comparison. These scripts use the MMSegmentation configuration files in `mmsegmentation/` and the checkpoint path configured in the analysis scripts.

## Notes

- Large raw and processed image data are not intended to be stored in this repository.
- Classical segmentation performance depends strongly on threshold, foreground polarity, magnification, tile stitching, and whether organoids are cystic, dense, single, or multiple per image.
- For new imaging protocols, validate masks visually using `inference_comparison/` before interpreting morphology plots.
